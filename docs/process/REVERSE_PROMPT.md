## 2026-10-25, preparation for the first publication

**Goal.** Complete the work before initial publication that needs no operator input,
and flag what does.

**Done.**
- **License notices.** The wheel links Rust crates under MIT, BSD-3-Clause, Unicode-3.0
  and other licenses that require their notices in binary copies, and shipped only the
  project's own license. `THIRD_PARTY_LICENSES.txt` now reproduces the texts of the 56
  linked crates, generated by `tools/third_party_licenses.py`, listed in
  `license-files`, checked by a test and asserted in each built wheel.
- **Distributions.** The sdist leaves out agent files and scratch, builds into a working
  install in CI, and both distributions pass `twine check --strict` locally.
- **Metadata and README.** Project links, keywords and classifiers. An installation
  section, and absolute links, because relative links break on the PyPI page.
- **Publishing.** A publish job in `wheels.yml` uses trusted publishing, runs only from a
  `v*` tag matching the built version, and waits in the `pypi` environment. The action
  is pinned to v1.14.2 by commit, because v1.14.3 was five days old.
- **Policy and procedure.** `SECURITY.md` and `docs/process/RELEASING.md`.
- **Coverage.** CI now tests Python 3.13 and 3.14 on Linux, which the classifiers claim.

**Needs the operator.**
1. **Before any tag is pushed, create the `pypi` environment** with a required reviewer
   and a `v*` tag rule. Fact. GitHub creates a missing environment unprotected, so the
   publish job would otherwise run without approval once PyPI trusts the workflow.
2. **Register the trusted publisher on PyPI** for `pykeleusma`, as `RELEASING.md` lists.
   Both names returned 404 on PyPI on 2026-10-25, which suggests but does not prove
   they are free.
3. **Enable private vulnerability reporting**, and review `SECURITY.md`, which I wrote
   as a default. It names the reporting channel, the supported versions and the scope.
4. **The license expression.** The metadata says `0BSD`, which describes the binding's
   own code. The wheel also contains MIT, BSD-3-Clause, Apache-2.0 or MIT, and similar
   code, with every text reproduced and no choice made among the alternatives of
   dual-licensed crates such as `self_cell`, Apache-2.0 or GPL-2.0-only. Whether the
   expression should name the bundled licenses is a judgement for the operator, and
   possibly for legal advice. I am not qualified to settle it.
5. **Release contents.** Whether to ship with the limitations blocked on Keleusma,
   listed in `HANDOFF.md`. Whether Alpha is the right development status. Whether
   musllinux, Windows on ARM64 or free-threaded wheels are wanted, none of which are
   built, so those users build from the sdist or cannot install.
6. **The release itself.** The date in the CHANGELOG, removing the sentence that
   nothing is published, the tag, and approving the deployment. PyPI never accepts a
   file name twice, so a published version cannot be replaced.
7. **Optional.** A TestPyPI rehearsal, which is not set up.

**Verification.** 406 Python tests and 49 Rust tests pass locally, with pyright, ruff,
rustfmt and clippy clean. Deleting one line of the notices file made the packaging test
fail. The publish job has not run, and cannot be exercised without a tag.
