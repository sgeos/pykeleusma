# Version 0.1.0

> **Navigation**: [Roadmap](./README.md) | [Documentation Root](../README.md)

The minimal binding against Keleusma 0.2.2. The tasks are ordered so that each depends
only on the ones before it. The first task settles the main design risk.

| # | Task | Done when | Status |
|---|---|---|---|
| 1 | Own the arena and VM together in a `#[pyclass]`, using `self_cell` | A test constructs, calls and drops many VMs, and the process's memory does not grow with the count | Done 2026-10-24 |
| 2 | `keleusma.compile(source)` returning a module | A compile error raises an exception carrying the line and column of the `Span` | Done 2026-10-25 |
| 3 | `keleusma.VM(module)` with an arena sized to survive `Reset` and composite arguments | A module that fails verification raises, and the message names the failure, and a stream runs 10,000 iterations with tuple arguments in an automatically sized arena | Done 2026-10-25 |
| 4 | Scalar, string, tuple, array and `Fixed` conversion, decoding composites by the entry point's declared types | Round trips pass for every shape in the Dromon probe, a `Fixed` round trips exactly, and out-of-range integers and bytes raise instead of wrapping | Done 2026-10-25 |
| 5 | `vm.call`, `vm.resume` and the state result | A script that yields three values and then finishes is driven to completion, and 1,000 VMs created on one thread are each resumed in turn | Done 2026-10-25 |
| 5b | `vm.wcet_per_iteration` and `vm.arena_capacity` | Both are readable from Python, and the documentation states their units and that they cover only the script and declared native bounds | Done 2026-10-25 |
| 6 | `vm.stream(...)` as a generator | Iteration ends on `Finished`, and a `Reset` has a stated meaning | Done 2026-10-25 |
| 7 | `vm.register(name, callable)` and `vm.set_native_bounds` | A Python exception raised inside a native reaches the caller as a Python exception, not as a crash, and declared bounds are either covered by the arena or rejected | Done 2026-10-25 |
| 8 | Examples | A PyGame frame loop that resumes once per frame, a NumPy reduction passing lists, and a batched update loop in Dromon's event and action shape, each run in a test or a documented manual check | Done 2026-10-25 |
| 9 | Documentation of the guarantee boundary | The README states that worst-case bounds cover the script and declared native bounds, not Python code | Done 2026-10-25 |
| 10 | Continuous integration | Lint, type checks and tests on Linux and macOS for Python 3.12 and the newest release | Done 2026-10-25 |
| 11 | Shared data blocks, kept by the VM in Rust and synced with a host buffer | A script reads and writes a host buffer through its shared `data` block, and a failed call leaves the buffer unchanged | Done 2026-10-25 |
| 12 | Coverage of the functionality the Keleusma book describes | The crate's example scripts give their stated results, and recoverable native errors, recovery, libraries, bytecode, signing, encryption, hot swap, structs, enums and options each have tests, with Keleusma defects reported | Done 2026-10-25 |

Tasks 4 and 7 grew on 2026-10-24, when the operator decided that `Fixed` converts to an
exact Python value and that native bounds are exposed. The design records both choices
and the risk each carries. Task 3 removed the temporary `_OwnedVmProbe` class that
task 1 added for its tests.

Tasks 3, 4, 5 and 8 grew, and task 5b was added, on 2026-10-25, when the operator
approved the changes proposed for Dromon, the first project to plan on this binding. Its
needs are in `docs/architecture/KELEUSMA_INTEGRATION.md` of the `pydromon` repository.
Task 3 also fixes a defect in task 1, whose arena is too small after the first `Reset`.
Task 7 stays in 0.1.0 after the tasks Dromon needs, because Dromon uses no natives.

Task 3 was done on 2026-10-25 with an empirical regrowth margin and a host-chosen
argument budget, because `v0.2.3` had not yet answered how a host should size the
arena. Its 10,000-iteration test runs in Rust, since Python cannot drive a stream until
task 5. It also exposed `vm.arena_capacity`, which task 5b documented.

Task 4 was done on 2026-10-25. It also added a compile-time guard against mistyped
yields, after finding that Keleusma 0.2.2 can crash on them. Task 5 replaced the
private `VM._call` hook that its round trips first used.

Task 8 was done on 2026-10-25 with one deviation. Keleusma 0.2.2 requires every stream
to yield and rejects an inner loop without a static bound, so an iteration of a
`loop main` is always one yield and one `Reset`. The PyGame loop therefore advances the
stream one iteration per frame, which is two resumes, the one that completes the
previous iteration and the one that starts the frame's own, rather than the single
resume the done-when column names. All three examples run in tests, PyGame headless
through SDL's dummy drivers, using NumPy and `pygame-ce`, which the development
dependencies now include.

Task 9 was done on 2026-10-25. The README's section "What is guaranteed, and what is
not" states the boundary, and a test pins its claims and runs the README's example.

Task 11 was added and done on 2026-10-25 at the operator's instruction, relayed by the
`pydromon` line in `pydromon-20261025-data-segment-request`, so that a stream processor
can keep state in its module's declared data block.

Task 10 was done early, on 2026-10-25, at the operator's instruction, so that every
later task merges through a remote check. It tests Python 3.12 and 3.15.

Task 12 was added and done on 2026-10-25 at the operator's request that the binding
act as a bridge for everything the Keleusma book describes. It brought structs, enums,
precompiled bytecode, hot swap and signed modules into 0.1.0, which were out of scope
before. What it could not cover, and the Keleusma defects it found, are in the design
under Book coverage.

Out of scope for 0.1.0, as recorded in the design: zero-copy NumPy buffers,
free-threaded Python and a PyPI release. Publishing needs the operator's confirmation in session.
